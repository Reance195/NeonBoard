## 三、仍开放的痛点与解决方案分析

### 1. `agent-init -InPlace` 脏树洗白通道（ZCode 记忆，R16-05 实测）
**现象**：脏工作区里跑 `-InPlace -Card`，领用提交把无关实现改动卷进去；`task_gate.py` 对
`chore(claim)` 整体豁免（`cmd_message` 176-177 行、`cmd_push` 437 行），代码进审计线却无短号凭证。
**方案分析**：两条根治路径——① agent-init 领用提交前检测脏树即拒绝；② `PROCESS_SCOPES` 豁免加
「触及代码路径即失效」条件。两条不冲突，建议立一张 DX 卡一起做：流程提交是空提交，正常情况
永不触及代码路径，加条件不伤豁免本意。领用前先 `git status` 的手工纪律只是止血。

### 2. board.yml 中间态红灯 → 每次收尾 1~3 封失败邮件
**现象**：git-done 分步快进补推（合并/清理/结卡/快照各一推），中间态 `derive --check` 必然
exit 1，board.yml 对每个不自洽中间态判红并通知维护者（实测 R16-05 三封、R5-08/R5-10 各两封）。
**方案与状态**：请求单 DX-44 已给出方案——`concurrency.cancel-in-progress` 翻 true（job 40s、
推送间隔 8s，中间 run 被取消且不发通知），判据落点自动挪到 main tip，同时保住「眼睛还在」
（人为只推合并不推快照的演练必须仍红）；二期方案 A（收尾三步合并为一次补推）动 `git-done.ps1`，
值得单独立卡。**本请求单已随本文收录入库，等维护者批准立卡。**

### 3. pitfalls §7 遗留（需人拍板，agent 不可自决）
- **7.6 R0-11 冷启动治本**（deploy.ps1 只随包 Basic 样式 + CMake DELAYLOAD，预计砍掉 CI 冷 I/O
  大头）——诊断已定案，卡在「扩 scope 还是立新卡」。建议立新卡：R0-11 已拖多日，扩 scope 要走
  授权行，不如干净开卡。
- **7.2 发版提交在锚点区分叉**：分叉已解除但流程未固化。建议给 `release.ps1` 加护栏
  （检测锚点区有未提交改动即报错），一行防御。
- **7.5 第三方工具产物落点无治本约定**：`.gitignore` 逐个点名是负债，需要拍板「谁注入目录约定」。
- **7.3 codex profile** 不达内置标准、**阶段条不监听 roadmap 文件**（DX-04 遗留）。
- **pre-push 规则 1 与 §7.2.1「分支必须推 origin」的矛盾**：已由并行批次立卡 **DX-45**
  （nbflow approve 收尾撞同一规则），从开放项转为跟进项。

### 4. 台账当前状态（2026-11-05 核实）
总卡 163 / 未结 10：DX-35~39、DX-41、DX-43、DX-45~47。其中 **DX-41（自动结卡提交缺 # 标记）
的修复合入了主线（b257ab7）但提交缺 `#DX-41=done` 标记**，卡仍挂 todo——恰好落在它自己要修的
问题域里，等验收闭环或补结。DX-43（一键立卡发区 card-approve.ps1）与 DX-45~47 在办。

### 5. Bash CWD 漂移（ZCode 记忆，工具层问题无法在仓库根治）
**缓解方案**：除「每条命令显式 `cd`/`git -C`」纪律外，可加一道程序化防线——`git-done.ps1` /
`agent-init.ps1` 入口校验 `git rev-parse --show-toplevel` 与预期工作区一致，不一致即中止并打印
两棵树路径，把「静默漂移」变「响亮失败」。一张小卡的成本。

### 6. 收尾顺序无自动化测试（结构性风险）
git-done 三步收尾提交「要真 push 才跑得到」，DX-20 改坏时所有检查全绿、端到端才炸。长期解是往
`verify.ps1` 加 dry-run 收尾档（对 fetch/push 打桩），属脚本架构改动，建议独立 DX 卡评估。

## 四、记忆体系元分析

1. **「程序覆盖即删」原则运转良好**，是这套体系最值得保持的纪律——教训一（给 CI 装闸门必须
   同时声明豁免面）与教训二（豁免要跟着实现一起回收）都已双双向脚本化收敛。
2. **最重的结构性风险只剩一个**：收尾顺序无自动化测试（见第三节第 6 条）。
3. **痛点→闸门的管道速度是真实护城河**：6 天里「踩坑→立卡→修复→固化」最短当天完成
   （DX-17 目录式 scope）。当前瓶颈已不在修复速度，而在**请求单编号与台账的竞态**——
   本次撞号即为例证。根治方向是把「建议编号占用检查」做进 `scripts/nbflow.py`
   （DX-44 请求单已自我标注此缺口）。
