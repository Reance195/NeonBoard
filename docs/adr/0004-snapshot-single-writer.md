# 0004. 进度快照只有一个写者：git-done 收尾写，CI 与脚本都不写

- 状态：accepted（追记 R14-01 / DX-106 已生效决策）
- 日期：2026-11-08
- 关联：宪章 §十一、`src/RoadmapSync`、`scripts/derive_board_status.py`、
  `git-done.ps1` 的 `Sync-BoardSnapshot`、`.github/workflows/board.yml`、
  `d064c12`（R14-01 收尾回滚后的人肉补提交）、v2 覆盖 v3 事故

## 背景

双写者时期，`progress.json` 这份派生文件同时被 CI 的 `derive --write` 补推和本地收尾写：
两边写同一文件必然撞车——谁先推谁赢、另一个白干；脚本是 fail-soft 的，失败只留几行
「补推失败」；撞车后 `rebase` 还会因为两份内容重叠而 abort。另一类症状是投影过期：
应用写回的是它内存里的状态，可能落后于本分支的 `#code=done` 标记（R4-02 已 done
却被写回 `doing`，一度靠 CI 事后纠正）。还发生过 agent 手改快照导致 v2 覆盖 v3 的降级事故。

## 决策

1. **写入路径只有两条，都在本地**：看板应用（`RoadmapSync` 自动写回）与 `git-done`
   收尾的 `derive --write`（提交前按 git 事实校正）。**CI 不是写者**，`board.yml` 只校验。
2. agent 与任何脚本**不得直接改 `progress.json`**；卡片状态变更走事件 → 插件 → 应用落盘闭环。
3. 收尾对 `origin/main` **只推一次**（DX-106）：合并提交与清理登记/结卡/快照本地提交后
   合成单次推送，快照在推送前刷新完毕，推送落点天然自洽。
4. 快照结构不降级：`version` 保持 3、每卡保留 `code`，移除的卡写 `"deleted": true`；
   由 `pre-push` 闸门拒绝降级推送。

## 理由

- 同一份派生文件永远只能有一个写者（宪章 Z5/Z15）；校验者可以有很多个。
- 单推送消灭中间态：每批收尾只产生 1 个 run，「红灯落在半途的旧 tip」在结构上不可能发生，
  于是判据可以钉死为**只看 main tip**。`board.yml` 的 `cancel-in-progress` 与沉降等待
  降级为纯双保险，保留只为防未来重新出现多次推送时回归。
- 「CI 事后补」曾被依赖，它把收尾失败藏进绿潮里；现在收尾失败必须显式可见、照提示补跑。

## 后果

- 正面：main tip 红 = 收尾真的失败了（离线 / 撞车 / 脚本失败），处置动作唯一——补跑收尾；
  派生文件不再有竞态。
- 负面：收尾若失败（如 R14-01 三件收尾全部回滚、靠人肉补 `d064c12`），main 快照会短暂过期
  直到补跑完成。我们接受它，因为这段过期是**带告警的显式状态**，不是静默错账。

## 备选方案

- CI 定时兜底补写快照：未选——那是第二个写者，正是被本决策根除的对象。
- 双写者 + 分布式锁：未选——锁拦得住文件竞态，拦不住语义漂移（陈旧投影照样能合法写入）。

## 验证方式

`derive_board_status.py --check`（board.yml 每次跑）；DX-106 推送次数断言（verify 脚本层）；
`pre-push` 快照闸拒绝 v2 / 卡片数减少 / 丢 `code`；看 main tip 单次 CI 结论即可判定收尾成败。
