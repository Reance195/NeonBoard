## 目标

发布 v0.1.10：把版本号从 0.1.9 递增到 0.1.10，并给随源码发布的内置中文版本摘要补上
0.1.10 一条，让刚落地的「更新中心 → 版本历史」在用户升级后立刻能看到这一版的变更要点。
打包、Release 资产、增量包与 update.json 回写全部由 CI（release.yml，tag 触发）产出，
本地 `dist/` 仅调试用途（§7.8），本卡不重复出包。

## 验收

见 frontmatter `acceptance`（6 条）。时序沿用 R5-16 口径：第 1/2/3 条在合并前核验；
第 4/5/6 条结构性排在合并与打 tag 之后，tag 推送后按清单逐条核验，失败即按 CI 报错修复重发。

## 边界

- 不动 installer/*.iss（版本号唯一来源是 CMakeLists，iss 只留兜底常量）；
- 不动 update.json（CI 的 build-update-manifest.ps1 单一写者，本地手写必漂）；
- 不本地出包（release.ps1 仅调试，交付物 CI 一处产出）；
- 不改更新链路代码 / QML / 发布流水线；release-history.json 只追加一条，不改写既有条目。

## 输入

基线 origin/main（5ca5591），本地 main 与 origin/main 一致。
流程依据：docs/git-workflow.md §三.5、AGENTS.md §7.8、docs/auto-update.md 版本历史维护约定；
先例：v0.1.9 发版提交链（R5-16，docs/card-requests/20261114-r5-release-v019.md）。

## 产出

CMakeLists.txt 版本号递增提交 + release-history.json 摘要追加（带 #<短号>）；
tag v0.1.10；CI 发布 run 与 GitHub Release（CI 产出）；update.json 同步提交（CI 回写）。
