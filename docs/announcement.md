## 一句话

NeonBoard —— 一个赛博霓虹风格的三列任务看板，Qt 6 + QML 写的 Windows 原生应用，完全离线，数据在自己磁盘里。

> 完全离线，SQLite 存本地，安装包 52MB，便携版解压即用。

## 长版（掘金 / 少数派 / Reddit r/Qt）

标题：**我用 Qt 6 + QML 写了一个赛博霓虹风的任务看板，顺手把「任务状态」接进了 git 提交**

正文结构：

1. **为什么又造一个轮子**
   现有看板要么 Tauri/Electron（启动慢、占内存），要么云同步（不想把待办交给别人服务器）。
   目标：单文件、离线、开机 1.5 秒内可用、键盘优先。

2. **技术选型**
   - Qt 6.8.3 + QML：原生渲染、单文件分发、Shader 直接写在 QML 里
   - C++20 承载模型层（SQLite、插件宿主、热键、托盘）
   - 插件系统：`.neon` 单文件包（manifest + files 的 JSON），市场走 GitHub/Gitee raw，SHA-256 校验

3. **几个我觉得有意思的设计**
   - **自然语言解析**：`明天 15:00 #工作 !3`，中文日期/时段/标签/优先级
   - **路线图上板**：提交信息里写 `#R5-03=done`，CI 从 git 历史和台账推导卡片状态并回写快照——**进度不靠人拖卡，靠 git 历史**
   - **多 agent 并行**：每个 agent 独立 worktree + 沙箱数据目录，领用走服务端 `refs/claims/<短号>` 占位，CI 拦绕过
   - **任务卡五段式**：目标/验收/边界/输入/产出，`scope` 由 CI 校验，越界改动直接红

4. **踩过的坑**（真实、有细节 → 是长文最值钱的部分）
   - 启动 9.7s → 1.4s 的剖析过程
   - 自动更新「下载完永远停在无法读取文件」：产物只校验没落盘
   - 三源串行 + 单源 10 秒超时吃光总预算

5. **现在什么样 / 缺什么**
   - 已发布 v0.1.2，Windows 10/11
   - 缺：安装包未签名、只有中文界面（英文 README 刚加）、插件生态刚起步

6. **求反馈**
   最想知道：启动速度、拖拽手感、插件 API 够不够用。
