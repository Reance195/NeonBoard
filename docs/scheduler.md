# 定时任务：到点即动作

给看板配时间计划，到点自动建卡、流转任务、发通知——plan-hook（提交事件驱动）的时间驱动姊妹篇。

```text
规则：每天 09:00 → 建卡「晨会」到 待办
规则：每周五 18:00 → 「进行中」列全部流转到 待办
规则：一次性 2026-12-31 20:00 → 通知「跨年复盘」
```

## 组成

```text
plugins/scheduler/
   ├─ background.qml   后台常驻：30 秒巡检到期规则 → 执行动作 → 推进槽位状态
   ├─ rules.js         规则引擎（解析 / 槽位计算 / 执行，前后台共用一份实现）
   └─ main.qml         面板：规则编辑 + 立即执行 + 执行记录
```

宿主不认识任何具体计划：巡检、幂等与执行全部在插件里。

## 安装

`plugins/scheduler/` 是官方插件，**随安装包分发**（同 [plan-hook](plan-hook.md) 的安装说明：来源 `appdir` / `official`，声明权限启动时自动补授，不弹授权窗）。侧栏「插件」→ 插件库里出现「定时任务」，点开即面板；后台巡检在应用启动时自动开始，**不需要打开面板**。

## 计划

三种计划类型，全部按**本机本地时间**解释：

| 类型 | 字段 | 示例 |
| --- | --- | --- |
| 每天 | `time`（HH:MM） | 每天 09:00 |
| 每周 | `time` + `weekdays`（1=周一 … 7=周日，可多选） | 每周一、三、五 09:50 |
| 一次性 | `onceAt`（具体日期时点） | 2026-12-31 20:00 |

## 动作

每条规则带 1..N 个动作，到点按顺序执行：

| 动作 | 字段 | 行为 |
| --- | --- | --- |
| 建卡 | 标题、状态、标签、备注、N 天后到期 | `addTask` 建卡，非默认字段一次 `updateTask` 补齐 |
| 流转 | 标题含 / 标签等于 / 来源列 → 目标状态 | 命中的任务逐个移到目标列**末尾**；标题与标签是「或」关系，都空时必须有来源列（显式整列流转） |
| 通知 | 标题、正文 | 托盘气泡（需 `notifications` 权限，官方来源自动补授） |

## 规则存储与幂等

规则存插件 storage（`board.db` 的 `plugin_kv` 表，键 `scheduler.rules`），面板与后台共用同一份，**改规则不需要重启**（后台每 30 秒重读）。

幂等靠**槽位键**：每天 → `daily:YYYY-MM-DD`，每周 → 最近命中日的 `weekly:YYYY-MM-DD`，一次性 → `once:<时间戳>`。只有「最近到期槽位」严格晚于「上次触发槽位」（storage 键 `scheduler.state`）才执行，因此：

- 同一时点至多执行一次（30 秒巡检粒度内不重复）；
- **补执行**：退出 / 关机期间错过的槽位，下次启动后只补执行最近一次，不逐日重放；
- **不追旧账**：新建「每天 / 每周」规则或修改计划字段后，从当前时点起生效——新建「每天 09:00」时若当天 09:00 已过，今天不会补发，明天才开始；**一次性规则例外**：指向过去时点的一次性规则视为显式补执行诉求，首次巡检即触发一次（只此一次）。

## 手动执行

规则卡片上的「立即执行」直接跑一遍动作并记入执行记录（来源标记「手动」），**不动槽位状态**——不会影响下次到点触发。用于验证规则、补建卡。

## 应用没开的时候

应用退出期间不会有任何动作。下次启动后，后台插件的第一次巡检（约启动后 30 秒内）会补执行错过的最近一个槽位（见上「幂等」）。

## 排错

| 现象 | 排查方向 |
| --- | --- |
| 到点没动作 | ① 规则启用了吗（卡片右侧开关）② 应用当时开着吗（关着则启动后补执行最近一次）③ 日志里搜 `scheduler:` |
| 建卡动作没建出卡 | `tasks.write` 权限被撤销了吗（设置 → 插件 → 授权记录）；执行记录里应有「异常」提示 |
| 通知没弹出 | `notifications` 权限同上；Windows 侧「专注助手」也可能吞气泡 |
| 流转了不期望的卡 | 流转动作的三个条件是过滤关系，先用「立即执行」验证匹配面 |
| 时间不对 | 计划按本机时区解释；改过系统时间 / 时区后以当前本地时间为准 |

日志位置：`%APPDATA%\com.lin\NeonBoard\neonboard.log`。

## 边界

- 只在**本机**生效；计划按本地时间解释，不处理跨时区 / 夏令时的特殊语义。
- 巡检粒度 30 秒：触发时刻最多晚于计划时点 30 秒。
- 执行记录只保留最近 20 条（storage 键 `scheduler.records`）。
- 动作失败不重试：逐条记入执行记录与日志，槽位照常推进（fail-soft）。
- 与宿主的提醒功能不重叠：卡片截止时间（due_at）的逾期提醒由 `ReminderScheduler` 负责，本插件只执行你配置的计划动作。
